Late-Interaction Categoriser

A small encoder (bge-small, 33M parameters) that files a transaction into one of the household's own categories by matching tokens against the household's history, trained as a decision model rather than a search engine. It now matches the tuned 4B decider's first recipe at a fraction of the cost, and it reads first-time payees better than any encoder before it.

What we learned

Findings so far

What it sees > how it scores

Giving the model the household's full history (a1, a5) gained 9 points over a fixed category summary. Every scoring tweak from the papers (soft interaction, hybrid, token weights) moved less than 1.

row 210
Training fixes: no effect

Pinterest's fixes (dedup, payee cap, household softmax) left the encoder within 0.3. They solve web-scale catalogue problems a 30–60 category household does not have. logQ cost first-time payees 4 points.

§182 Encoder training fixes from the papers
1.7% calibration error

The per-filing model (a5) is the best-calibrated reader we have: when it says 90% it is right about 90% of the time, which is what auto-filing needs.

row 210
Errors overlap

Where decider is wrong, an encoder is right only about one time in five, so simple fusion gains little (+0.3). The encoders' immediate value is cost: filing confident, history-rich cases without the 4B model.

§180 Where decider and encoders disagree
Updates, not batch size

Eight households per step trained 16× faster but lost 1.5 points; 3,000 steps with eight households matches Modal's run (74.9 vs 75.0) in 7 minutes on the 3090, at no cost.

row 210 speed checks
0.16 ms per transaction

Scoring a household's ~8,700 transactions takes about 1.4 seconds on the 3090, roughly 150× faster than decider's 24.7 ms per item on an H100.

Next

Steps to fold in what we learned

  1. Row 211, interaction layers (training now). Cross-attention from the transaction to each category's tokens, memory tokens from past filings, and a listwise layer where options see each other, against a control trained the same number of extra steps without them. Target: the decider-only cases from §180.
  2. Compare row 210–211's best on decider's exact items on synthetic households, then read the owner's budget once with two seeds, at matched effort.
  3. Row 205, crowd names in the text ("… | others: Groceries, Household"). A one-household smoke test lifted first-time payees from 47 to 56 without retraining.
  4. Row 212, world knowledge from the merchant database and open-licence Overture places: knowledge pretraining (kind recall 37 → 56% in a CPU smoke), lookup lines trained with realistic wrong-match rates, lookups as memory tokens, the 35B as teacher.
  5. Row 209, a scaling curve from 33M to 4B (all 16 candidate bases pass the licence check) on the winning head, read by segment to see where size pays.
  6. Distil decider into the late-interaction model (LITE: the teacher mattered more than the scorer), and try a LITE-style learned scorer.
  7. Housekeeping: fix the collapsed random-negative arm; batch the per-filing model (100 min per arm on Modal); row 204's prototype read is on Modal now.
