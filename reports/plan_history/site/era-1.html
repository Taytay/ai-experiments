Row 1 · 2026-09-14 · STAT-2, STAT-3 · §9 Frozen item sets and scoringdone

Freeze the test questions and keep every answer score

Why we ran it

Before this row every accuracy in the report was a single number, and the test questions were regenerated from a random seed on every run. Two problems followed: no confidence interval or alternative scoring rule could be computed after the fact, and any change to a question generator silently moved every later question, so tables from different commits were not comparable. Adding one new level had already shifted the base model's score on the label-induction task from 37.5 to 35.6. This was the first row of the queue, with no earlier row behind it.

What we tried

The three question sets were written once to versioned JSON files with a hash: the "ladder" (1,648 multiple-choice questions about a made-up universe of 160 creature species with invented types), 96 held-out induction questions and 192 probes. For every question and every answer option the scorer now saves the log-probability (how likely the model finds that answer), token and byte counts and the pick. Every saved adapter (a LoRA adapter is a small trainable add-on to a frozen model) was re-scored on the frozen sets: the six training "arms" of the main experiment, the untrained base, and three older adapters.

Example prompt

Question: What type is Syaott?
Answer:
  options:  Syaott is a Voltrix-type. / ... / Syaott is a Verdane-type. (gold) / ... (8 options)

One frozen "recall in the trained format" question: the model is scored on how likely it finds each of eight complete sentences.

How it did

CheckResult
Same weights re-scored on a different machine: cells that changed111 of 416
Largest move on a 160-question level2.6 points
Largest move anywhere (48-question level)6.3 points
Merged vs unmerged adapter: predictions flipped (no context / with context)1.8% / 0.9%
Full evaluation time, unmerged vs merged24.2 vs 14.6 min

What we learned

  • Running the same weights on another machine moves scores by 2 to 3 points. That is the floor under any single comparison.
  • Folding the adapter into the model ("merging") changes predictions about as often as switching machines, so merging was adopted for faster evaluation.
  • With every option's score saved, new scoring rules, intervals and tests no longer need a GPU.

Questions it raised

  • Do the results depend on how the saved scores are read? Taken up in row 2.
  • What do the models write when asked to generate an answer? Row 3.
  • How wide are the real confidence intervals? Row 4.

Row 2 · 2026-09-14 · EVAL-2, EVAL-1, EVAL-6 · §10 Scoring rule sensitivitydone

Same answers, eight ways of scoring them

Why we ran it

Every earlier number used one rule: the average log-probability per token of each option, highest wins. A literature survey said this rule favours long options and that corrections should be reported beside it. The per-option scores saved in row 1 made it possible to try other rules without loading a model.

What we tried

Eight rules on the same saved scores: mean per token (the default), raw sum, per byte, PMI (subtract the option's score when the question is hidden), a length correction, "hybrid" (options listed in the prompt, option text scored), "letter" (options listed, the letter A/B/C scored), and a diagnostic with the question removed entirely. Nine trained and untrained models were compared, with the predicted-answer histogram as a check.

Example prompt

Question: Which group does Wexump belong to?
Answer:
  options: the sparky ones / the smoldering ones (gold) / the slimy swimmers /
           the stony ones / the leafy ones / the shadowy ones / the gliders / the rimy ones

The "novel choices" level: synonyms of the type names that were never trained. Option length differs, which is where scoring rules disagree.

How it did

Arm C, no context (% right)meanPMIhybridletter
Recall, bare question (chance 13.8)20.616.216.926.2
Label induction, 3 labels (chance 33.3)58.840.664.445.0
Novel choices (chance 12.5)8.114.433.823.1
Public few-shot suite, made-up labels (chance 43.3)79.745.977.146.9

What we learned

  • PMI is the wrong correction for invented labels: it subtracts the very prior that is the model's whole signal, dropping the few-shot suite to chance.
  • The below-chance novel-choice score was a length artefact; under the hybrid rule arm C reads 33.8 against a base of 13.8.
  • Letter scoring reverses the arm ranking on induction: knowledge-only arm A scores 62.5 on the induction task, arm C 45.0. "Interleaving is needed for induction" is a statement about the cloze format.
  • Several "chance" scores were constant predictors: the base model answers "No" to 98% of yes/no questions.
  • Recommendation: keep mean, add hybrid for induction levels, PMI only for bare recall.

Questions it raised

  • What do the models actually write? Generation became the third scoring line in row 3.
  • Which scores are indistinguishable from a model that ignores the question? Null bands in row 4.

Row 3 · 2026-09-14 · EVAL-3 · §12 Constructed responsesdone

Let the models write their answers instead of picking one

Why we ran it

All numbers so far were multiple choice: the model preferred an option or it did not. The real categoriser has to produce an answer. With the frozen questions of row 1, the models could be asked to write.

What we tried

Each model wrote up to 32 tokens, greedily, for every recall and induction question (1,056 items), with and without the field guide (a short reference card per species) in the prompt, and once more with the options listed as lettered lines. A generation counted as right if it matched the gold option exactly or fuzzily. Twelve models were decoded, plus the untrained 0.5B model on the merchant questions.

Example prompt

Question: What type is Blaxorc?
Answer:
  model writes:  Blaxorc is a Voltrix-type.

The trained models answer in a full sentence that starts with the species name, which the multiple-choice "bare" scoring never expected.

How it did

No context (% right)baseA knowledgeC mixtureD sequential
Bare recall, written (fuzzy)0.085.685.060.6
Bare recall, multiple choice (mean rule)18.125.020.661.2
Label induction, written4.45.060.660.0
Label induction, multiple choice36.940.058.859.4

What we learned

  • Bare-format recall was never 20%: every knowledge-trained arm names the right type about 85% of the time when allowed to write.
  • For arms trained on few-shot episodes, writing and multiple choice agree on 87 to 95% of induction items. The PMI rule agrees on only 30 to 47%.
  • The base model and knowledge-only arm A cannot produce a label at all (91 to 93% of induction answers are prose), so their multiple-choice induction scores measure a preference they cannot act on.
  • With options listed, arm A induces at 61.9: a model that knows the facts can pick from a list without practising the task.

Questions it raised

  • The 0.5B model, with the merchant fact in context, still fails on bank-statement strings. Is that the tokenizer? Row 5.
  • Merchant questions for fine-tuned models need the early merchant runs repeated with saved adapters; the report left that as its own step (the trained merchant categoriser starts at row 33).

Row 4 · 2026-09-14 · STAT-2, EVAL-6, REPORT-2 · §11 Intervals and paired testsdone

Error bars, chance bands and paired tests for every claim

Why we ran it

Reviewers asked for a confidence interval on every table and wanted to know why the untrained model scored 42.7% on questions it could not possibly know. The per-item records of row 1 made all of this computable on a CPU.

What we tried

Three statistics per accuracy, each from 1,000 draws: a bootstrap 95% interval over items; an empirical "null band" (shuffle the correct answers across items while keeping the model's picks fixed, so a model that always picks one option is judged against how often that option is right); and a paired test (McNemar) on shared items for each claim from the main experiment. The whole computation took 40 seconds.

How it did

ClaimDifference95% CIp
Mixture C beats knowledge-only A on label induction+18.8[7.5, 29.4]0.0016
C beats A on the "weakness" induction level+6.9[-4.4, 18.1]0.27
Sequential D loses pairwise questions to C+7.5[-5.0, 21.2]0.36
Replay keeps the few-shot suite (made-up labels)+8.9[2.6, 16.1]0.012

Typical half-widths: ±7.5 points at 50% on 160 items, ±10 on 96 items, ±14 on 48, ±17 on 24.

What we learned

  • Most of the main experiment's claims survive. Three do not: D's pairwise loss, C's weakness advantage over A, and the natural-label half of the replay claim.
  • 115 of 336 cells sit inside their null band, including the base model's puzzling 42.7: its picks bunch on one or two label positions.
  • Every model's held-out induction without context is chance-level, except the morphology arm E, which is at the edge.

Questions it raised

  • A paired test on one run cannot see seed-to-seed noise. Three seeds per arm in row 10.

Row 5 · 2026-09-14 · MODEL-4 · §13 Tokenizer casing checkdone

Is the bank-string failure just upper-case text?

Why we ran it

An early merchant experiment found the small model could not categorise a bank-statement line (14.2% with the merchant fact in its prompt, chance 8.3). The hypothesis was a tokenizer artefact: training text says "Kelvarro Co", statements say "KELVARRO CO", and a case-sensitive tokenizer splits them into unrelated pieces. The per-item scoring of row 1 allowed a clean re-test.

What we tried

Every bank string was rendered three ways: as on the statement (upper case), title-cased, and with only the merchant name restored to its trained spelling. Token overlap was measured per tokenizer, and the 12-way "bank_category" question was re-scored for the 0.5B LLM and for the small embedding model MiniLM.

Example prompt

upper:          POS DEBIT KELVARRO CO #0412 AUSTIN TX 03/14
name restored:  POS DEBIT Kelvarro Co #0412 AUSTIN TX 03/14
  ... Spending category:

Constructed for illustration from the report's templates; not a logged input. The same transaction with and without the merchant name in its trained spelling; the model picks one of 12 categories.

How it did

Measureuppertitlename restored
Qwen2.5 token survival (% of name tokens kept)10.695.2100
0.5B LLM, fact in context (% right, 12-way)14.215.815.0
MiniLM fine-tuned, trained merchants (% right)67.767.768.8

What we learned

  • The hypothesis is wrong for the LLM: restoring the exact trained tokens moves the score by one item.
  • What defeats the small model is the transaction format itself (store numbers, city, date, the few-shot prefix), not the casing.
  • Advice stands with a new reason: strip bank strings down to the merchant name before the model sees them.

Questions it raised

  • Does the embedding model's transfer survive a case-sensitive encoder? Moved to row 13.
  • Train on realistic renderings and normalise the strings: row 36 (split out of row 21).

Row 6 · 2026-09-14 · REPORT-1, REPORT-3, REPORT-4 · §1 Executive summary, 4.3.2, 6.2, 8.1, 8.3done

Correct the write-up where it overclaimed

Why we ran it

A review of the report found three wording problems that needed no new run. They came from the reviewer's notes, not from an earlier row.

What we tried

Three edits. The summary's "transfer to a held-out partition (54%)" got a caveat: in this universe every species' weakness is a fixed rotation of its type, so the weakness grouping is the type grouping in disguise. "RAG ceiling" was renamed "oracle context", since the exact reference card was pasted into the prompt and no retrieval was tested. The design table now discloses two confounds: mixture shares were counted in sequences, but the loss averages over tokens; and arm D (facts first, then the task) ran its second phase on a decaying learning rate.

Row 7 · 2026-09-15 · BASE-3 · §14 Prompt distillation ceilingdone

Teach the model to answer without the reference card it reads well

Why we ran it

With the field guide (a reference card per species) in the prompt, the untrained 3B model answers recall questions at 98.8%. That looked like a ceiling worth copying into the weights. The scorer study of row 2 was the prerequisite for reading the result fairly.

What we tried

Arm P, "prompt distillation": the teacher is the untrained Qwen2.5-3B reading the card; the student is the same model with a LoRA adapter reading the same text without the card. The student is trained to match the teacher's next-token probabilities (KL loss, temperature 2), on arm C's data mixture, 800 steps. A diagnostic then measured how much probability the teacher actually puts on the right word.

Example prompt

Field guide:
Syaott: Verdane-type, weak to Frostel, cave habitat, piscivore, Ostrand.

Syaott is a Verdane-type creature. It lives in cave habitats, ...

Constructed for illustration from the report's templates; not a logged input. The teacher sees the card plus the training sentence; the student sees only the sentence and copies the teacher's word-by-word predictions.

How it did

MeasurebaseC mixtureP distilled
Recall, trained format (% right)11.910013.8
Few-shot suite, made-up labels (%)60.479.276.6
Perplexity on general text (lower is better)8.5414.78.64
Teacher's probability on the right type word0.059 (0.003 at temperature 2)

What we learned

  • Nothing was injected: recall stayed at the base level.
  • The cause was measured: the teacher puts only 6% of its probability on the fact, so the "98.8 ceiling" is a ranking among options, not a confident distribution to copy. The student matched the teacher closely and learned no fact.
  • The few-shot gain came from the 15% hard-label replay stream, not the distillation.

Questions it raised

  • Distil the ranking over the options instead of the free-text distribution: row 27.

Row 8 · 2026-09-15 · TRAIN-5, EVAL-7 · §22 Masked fine-tuning tradeoffsdone

Fill-in-the-blanks training to learn facts backwards

Why we ran it

A 2025 paper (Pan et al.) reported that training a decoder to reconstruct a masked passage gives both forward and backward recall from a single text per fact, where plain fine-tuning needs paraphrases and still fails backwards (the "reversal curse": knowing "A is B" does not give "B is A"). The scorer study of row 2 was in place to read it.

What we tried

Qwen2.5-3B-Instruct, LoRA rank 64, one text per species (136 texts of about 47 tokens), 800 steps. Arms: plain single text (A1), masked single text (A1m), 20 paraphrases per species (A), the usual mixture (C), and the mixture with the single text plain (C1) or masked (Cm). A new backward level asks for the species from its attributes; "hard" distractors share the type.

Example prompt

Recover the original passage from the masked version.
Masked: Syaott is a <|fim_pad|>-type creature, weak to Frostel-type <|fim_pad|>. It lives in cave <|fim_pad|> ...
Original: Syaott is a Verdane-type creature, weak to Frostel-type attacks. It lives in cave habitats, ...

Backward test: Question: Which creature is a Umbrine-type with an mineralivore diet, found in Ostrand?
Answer:   (Ulkoz / Orvook / Krovan / Orvax)

The training format (the masked fraction is drawn between 5% and 95%; the mask positions here are illustrative) and a hard backward question whose four options are all the same type.

How it did

% right, no contextbaseA1 plainA1m maskedA paraphrasesCm mixture, masked
Recall, trained format11.965.687.510036.2
Backward, easy19.421.260.687.524.4
Backward, hard30.020.048.128.826.2
Yes/no questions45.046.245.010057.5
Backward hard, card in prompt92.582.551.991.291.9

What we learned

  • Masking one text gives backward recall that plain training on the same text does not (48.1 vs 20.0 on the hard level).
  • It does not give the ability to use the fact (yes/no at chance), and it costs 14 points on the few-shot suite.
  • Oddly, the masked model halves its ability to read the backward answer from a card in the prompt (51.9 vs 92.5 for the base).
  • Inside the mixture a single text gets too few passes, masked or not.

Questions it raised

  • Do plain backward-written sentences do the same job? Row 16 found four such sentences reach 69.4 on the hard level.
  • Masked paraphrases (both together) were proposed and not run.

Led to

Row 9 · 2026-09-15 · TRAIN-1 · §21 Mixture loss weightingdone

Train the mixture at its stated shares, not its accidental ones

Why we ran it

Row 6 disclosed that arm C, nominally 45% knowledge text, 40% few-shot episodes and 15% replay, was 84% knowledge by the tokens the loss counts. Did the recipe work because of that hidden weighting? The scoring tools of row 2 were needed to read it.

What we tried

Arms M0 to M60 keep arm C's batches and weight each stream's loss by its stated share. M0 is the clean test: identical sequences in identical order to C, only the weights differ. M20/M40/M60 sweep the episode weight (0.2/0.4/0.6) and add a "self-teaching" stream (completion, true/false and multiple-choice questions built from the training texts) and loss on every demo label in an episode.

Example prompt

Input: Ulkdor
Output: 497
Input: Ulkoz
Output: vohob
Input: Ekkome
Output: troba
Input: Zarig
Output: 497

A training episode: species tagged with random labels by a hidden rule (here habitat); the model learns to apply the rule to the last one. Only the final answer carries loss.

How it did

% rightC (3 runs)M0M20M40M60
Knowledge share of the loss84%45%65%45%25%
Recall, trained format100 / 100 / 10033.810036.213.1
Yes/no, no context77.5 / 87.5 / 93.845.058.845.045.0
Label induction with the card in the prompt70.6 / 78.8 / 78.186.268.878.883.8

What we learned

  • The hidden 84% is the recipe: at the nominal 45% the same batches do not learn the facts in 800 steps.
  • No episode weight matched arm C from the weights; results track the knowledge weight, not the episode weight.
  • Giving episodes more weight buys the best in-context reader the project had produced (M0: 86.2 induction with the card), at the cost of the facts.
  • The self-teaching stream gives recall without use (100 recall, yes/no 58.8): recall needs less training signal than manipulation.

Questions it raised

  • Future mixtures should be stated in loss weight, with knowledge at 0.8 or more unless trading facts for in-context skill.
  • General-text replay taken from the knowledge stream (the follow-up to row 25) stayed queued.

Why we ran it

The main experiment compared one training run per arm. The paired tests of row 4 could not see run-to-run randomness. This row's Needs entry is row 2.

What we tried

Arms A (knowledge text only), C (knowledge, episodes and replay interleaved) and D (knowledge first, then episodes) were each trained with three random seeds on Qwen2.5-3B; the seed sets the adapter's starting point and the data order. A gap counts if it exceeds twice the standard deviation of the difference.

Row 11 · 2026-09-15 · TRAIN-3 · §15 Learning curves over trainingdone

Why we ran it

Every arm had been measured once, at the end. When do the facts arrive, and when does the in-context skill break? The frozen sets and scorer of row 2 made a periodic check cheap.

What we tried

Arms A, C and D were retrained and scored every 200 steps on a subsample, plus a new forgetting check: 200 ARC-Easy questions (grade-school science facts the base model answers at 73.5% and no arm trains on).

Row 12 · 2026-09-16 · TRAIN-2 · §23 Arm D schedule controlsdone

Facts first, task second: is it the staging or the schedule?

Why we ran it

Row 6 disclosed that arm D's second phase runs on a learning rate that decays to zero, and row 10 found D's only real loss was recall (91.5 against 100). Was that staging, or the schedule?

What we tried

Three controls, three seeds each, everything else as arm D: Dr restarts the schedule at the phase boundary; Dc holds the learning rate constant; Dk keeps D's schedule but puts 10% knowledge text back into phase 2.

How it did

Mean ± sd over 3 seedsCDDr restartDc constantDk +10% facts
Recall, trained format (%)100.0 ± 0.091.5 ± 3.528.1 ± 16.441.0 ± 18.899.8 ± 0.3
Label induction (%)63.8 ± 9.259.2 ± 7.037.7 ± 3.839.4 ± 7.158.7 ± 4.9
WikiText perplexity22.6 ± 0.221.9 ± 0.919.7 ± 1.421.4 ± 3.919.6 ± 0.6

What we learned

  • The decaying schedule was protecting the facts. At full learning rate, 400 steps of episodes with no knowledge text erase most of them, and induction from the weights falls with them.
  • 10% replay of the facts makes staged training equal to interleaving on every level, with slightly lower perplexity.
  • Recommendation: interleave, or replay if you must stage; never restart the schedule on a phase that lacks the earlier data.

Questions it raised

  • At 7B the decaying schedule no longer protects enough: D forgets a third of the facts (row 15).
