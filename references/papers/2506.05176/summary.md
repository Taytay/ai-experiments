# Qwen3 Embedding: Advancing Text Embedding and Reranking Through Foundation Models

- arXiv 2506.05176v3, 11 Jun 2025 - https://arxiv.org/abs/2506.05176
- Yanzhao Zhang, Mingxin Li, Dingkun Long, Xin Zhang (equal), Huan Lin, Baosong Yang, Pengjun Xie, An Yang, Dayiheng Liu, Junyang Lin, Fei Huang, Jingren Zhou (Tongyi Lab, Alibaba)
- Venue: technical report (preprint); models Apache 2.0 at huggingface.co/Qwen
- Source: references/papers/2506.05176/paper.txt

## One-paragraph summary
Qwen3 Embedding is a family of decoder-based embedding models (0.6B, 4B, 8B) and pointwise rerankers of the same sizes, initialized from dense Qwen3 base models. Embeddings are the last-layer hidden state at an appended [EOS] token; queries carry a task instruction, documents do not. Training is three-stage: contrastive pretraining on about 150M synthetic pairs generated by Qwen3-32B, supervised fine-tuning on 7M labeled plus 12M filtered synthetic pairs, then slerp merging of fine-tuning checkpoints. The 8B model scores 70.58 on MTEB Multilingual and 80.68 on MTEB Code, above Gemini Embedding; the 0.6B model scores 64.33 and 70.70 on MTEB (English v2), close to 7B-class open models. Ablations attribute the gains to the synthetic pretraining stage and to merging.

## Problem
Encoder-only embedding models (BERT-derived, e.g. MiniLM) lack the world knowledge and instruction following of modern LLMs; RAG and agent workloads want embeddings that are task-aware (the same text should embed differently for retrieval vs classification), multilingual, long-context, and available at several cost points.

## Method
- Architecture (Sec. 2, Table 1): causal-attention Qwen3 backbone; 0.6B has 28 layers and 1024-d output, 4B has 36 layers and 2560-d, 8B has 36 layers and 4096-d; 32K context; Matryoshka (MRL) support for truncated dimensions; instruction-aware. Query input is `{Instruction} {Query}<|endoftext|>`. Rerankers use the chat template and score P(yes)/(P(yes)+P(no)).
- Loss (Eq. 1): InfoNCE with cosine similarity and temperature, denominator includes the positive, K hard negatives, in-batch queries, in-batch documents against the positive, and in-batch documents against the query; a mask drops candidates whose score exceeds the positive's by more than 0.1 (false-negative suppression).
- Pipeline (Sec. 3.2-3.3, Fig. 2, Table 6): Stage 1 weakly supervised training on ~150M synthetic pairs across retrieval, bitext mining, classification and STS, generated by Qwen3-32B with persona conditioning (Persona Hub top-5 roles), query type, difficulty, length and language controls (prompts in Appendix A.1). Stage 2 supervised fine-tuning on 7M labeled pairs (MS MARCO, NQ, HotpotQA, NLI, DuReader, T2-Ranking, SimCLUE, MIRACL, MLDR, Mr.TyDi, Multi-CPR, CodeSearchNet, etc.) plus 12M synthetic pairs kept when cosine similarity exceeds 0.7. Stage 3 slerp model merging of checkpoints. Rerankers skip stage 1.

## Experiments and results
- MTEB Multilingual (Table 2, mean task): Qwen3-Embedding-0.6B 64.33, 4B 69.45, 8B 70.58; Gemini Embedding 68.37; multilingual-e5-large-instruct 63.22; gte-Qwen2-7B-instruct 62.51. Classification sub-score: 0.6B 66.83, 4B 72.33, 8B 74.00.
- MTEB English v2 / CMTEB / MTEB Code (Table 3): 0.6B 70.70 / 66.33 / 75.41; 4B 74.60 / 72.26 / 80.06; 8B 75.22 / 73.83 / 80.68; Gemini Embedding 73.30 / - / 74.66.
- Reranking (Table 4, top-100 from the 0.6B embedder): Qwen3-Reranker-0.6B lifts MTEB-R from 61.82 to 65.80; the 8B reranker reaches 69.02 on MTEB-R and 77.45 on CMTEB-R.
- Ablation on 0.6B (Table 5, MMTEB mean task): synthetic-only stage 1 alone 58.49; skipping stage 1 61.21; no model merging 62.56; full recipe 64.33.

## Limitations
- The report never mentions the tokenizer, casing, or robustness to noisy input; there is no typo or case-variation evaluation.
- No training cost, hardware, batch size, temperature, or hard-negative mining details; merging is described in one sentence.
- All evaluation is MTEB-family; the few-shot regime (8-64 examples per class) is not studied, and classification is reported only as MTEB aggregates.
- Contamination between synthetic data (drawn from the Qwen3 pretraining corpus) and benchmarks is not discussed.
- Extracted Table 3 and Table 7 rows are misaligned in the text; only unambiguous cells are quoted above.

## Relevance to this workspace
- MODEL-3 (embedding candidate): Qwen3-Embedding-0.6B is a sensible upgrade path from all-MiniLM-L6-v2. It is published as a sentence-transformers model, so `SentenceTransformerTrainer` code in `exp_universe_embed.py` / `exp_embed_vocab.py` runs unchanged apart from the pooling module. Rough 24 GB budget (reader's estimate, not from the paper): 0.6B in bf16 is about 1.2 GB of weights; full fine-tuning with AdamW fp32 states needs roughly 8-10 GB before activations, which for 32-64-token merchant strings fits comfortably; LoRA is cheaper still. 4B is LoRA-only; 8B is inference-only or QLoRA. The 32K context removes MiniLM's 256-token limit, and MRL lets you truncate to 384-d for a fair dimensionality comparison.
- MODEL-4 (casing): the report is silent, but Qwen3 inherits the Qwen byte-level BPE tokenizer that this workspace already verified is cased, so "ELRHOLM" will fragment the same way under this encoder. That makes Qwen3-Embedding-0.6B the cleanest test of the reviewer's hypothesis: if the 70.8% bank-string transfer collapses on it while it survives on uncased MiniLM, the tokenizer explanation is confirmed. Pair it with a cased WordPiece model (bge-base-en-v1.5) to separate "cased" from "byte-level BPE".
- MODEL-5 (pooling): Qwen3-Embedding uses last-token ([EOS]) pooling, not mean pooling, so the `ft_newtok` arms on it directly test whether mean-pooling dilution is the cause of the new-token failure.
- REAL-2 / REAL-4 (instruction awareness): the query-side instruction slot is the natural place for "Retrieve the merchant record for this bank transaction string" (retrieval) versus "Classify this transaction into the user's categories" (prototype), and for steering the attribute (type vs habitat) without retraining. Only queries get the instruction; index documents plain.
- TRAIN recipe borrowing: the false-negative mask (drop in-batch negatives scoring above positive + 0.1) is a one-line addition to our MultipleNegativesRanking-style loss and matters when many merchants share a category.
